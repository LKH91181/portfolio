1. 共性基建方案（一次解决一类问题）

1a. 鉴权体系设计

三条路线评估（场景：内网、HTTP 明文 http://*:10002、多客户端类型：门口屏/术间屏/导播/管控中心、WPF 客户端已持有 clientId）：

路线 优点 缺点 结论
JWT 标准化、无状态 服务是 HTTP 明文，JWT 载荷可被嗅探重放；所有客户端都要改造 token 获取/刷新；需引入 JwtBearer 包 不推荐（内网明文下收益低、改造面最大）
API Key（每客户端类型固定密钥） 改造小、服务端一个中间件搞定 密钥分发/轮换需运维配合；无法表达"用户级"身份 推荐，作为第一优先落地
现有 clientId 强化 零客户端改造 clientId 明文出现在 query、无签名、可枚举重放（f_011 已证登录无锁定） 不够，但作为兼容过渡层保留

推荐：API Key 为主 + clientId 强化兜底的渐进式方案，利用现有 ClientInfo.ExpiryDate（ClientManagerComponent.cs:76 已写死 DateTime.Now.AddDays(1)，系统本就有会话过期概念，只是从未校验）。

ApiKeyAuthMiddleware.cs 骨架：

public class ApiKeyAuthMiddleware
{
    public async Task InvokeAsync(HttpContext ctx)
    {
        var path = ctx.Request.Path.Value?.ToLowerInvariant() ?? "";
        if (_options.AllowAnonymousPaths.Contains(path)) { await _next(ctx); return; }

        var key = ctx.Request.Headers["X-Api-Key"].FirstOrDefault();
        if (string.IsNullOrEmpty(key))
        {
            // GracePeriod 兼容层：老客户端不带 Key 时，回退校验 query 中的 clientId
            if (_options.Mode == ApiAuthMode.GracePeriod
                && ctx.Request.Query.TryGetValue("clientId", out var clientId)
                && IsValidClient(clientId))   // ClientManagerComponent.Get + ExpiryDate > Now
            { ctx.Items["AuthSource"] = "legacy-clientId"; await _next(ctx); return; }

            await WriteError(ctx, 401, 401000, "缺少有效的 API Key 或 clientId");
            return;
        }
        var identity = _options.ResolveKey(key);
        if (identity == null) { await WriteError(ctx, 401, 401001, "API Key 无效"); return; }
        ctx.Items["AuthIdentity"] = identity;
        await _next(ctx);
    }
}

1b. 全局异常处理：统一 Response 包装，禁止 ex.Message/StackTrace 直出

新增 OPService/Filters/GlobalExceptionMiddleware.cs + OPService/Filters/ResponseFactory.cs：

public class GlobalExceptionMiddleware
{
    public async Task InvokeAsync(HttpContext ctx)
    {
        try { await _next(ctx); }
        catch (Exception ex)
        {
            Log.Error(ex);   // 内部日志落文件（现有 Log4net，Program.cs:220）
            await WriteResponse(ctx, ResponseFactory.FromException(ex));
        }
    }
}

public static class ResponseFactory
{
    public static object FromException(Exception ex) => ex is SysMsgException se
        ? new { error = se.ErrorCode, content = (object?)null, message = se.Message }  // 业务消息保留
        : new { error = 300000,   content = (object?)null, message = "服务器内部错误，请联系管理员" };
    // 关键：普通 Exception 一律替换为固定文案，ex.Message/ex.StackTrace 只进日志不进响应
}

存量 catch 块收敛（f_008 根因，30+ 处）：catch(Exception ex){ Message = ex.Message } 统一替换为 catch(Exception ex){ Log.Error(ex); return ResponseFactory.FromException<Response<T>>(ex); }。分两步：

// JsonQuery.cs —— 统一 JSON-in-query 参数解析（f_010 全家桶）
public static class JsonQuery
{
    public static (List<string>? codes, string? errMsg) ParseStringList(string? json)
    {
        if (string.IsNullOrWhiteSpace(json)) return (null, "参数不能为空");
        try {
            var codes = JsonHelper.FromJson<List<string>>(json);
            if (codes == null || codes.Count == 0) return (null, "参数为空数组");
            return (codes, null);
        } catch { return (null, "传入参数异常！"); }   // 语义对齐 CopilotController.cs:81
    }
}

// EnumCheck.cs —— 枚举强转防线（f_006/f_009）
public static class EnumCheck
{
    public static T Validate<T>(int value, string paramName) where T : struct, Enum
        => Enum.IsDefined(typeof(T), value)
            ? (T)Enum.ToObject(typeof(T), value)
            : throw new SysMsgException($"{paramName} 取值非法: {value}");
}

// PageQuery.cs —— 分页钳制（f_015）
public static class PageQuery
{
    public static (int page, int size) Normalize(int page, int size, int maxSize = 200)
        => (Math.Max(1, page), Math.Clamp(size, 1, maxSize));
}

空数组语义标准（写入开发规约）：查询类接口空选集 = error=0 + 空 content；写/操作类接口空选集 = error=300000 + "参数为空"。两者不可与"资源不存在"共用文案。
